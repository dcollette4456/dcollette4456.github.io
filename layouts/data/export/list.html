Data Export

Classification spec §25. Three static routes, generated at build. This is the product's actual argument: everything else in this system is a procedure for producing a dataset whose defining property is that somebody else can check it.

  • /data/export/sources.json · the source registry as rendered on the coverage pages, {{ len .Site.Data.sources.registry }} entries
  • /data/export/claims.jsonl · one flattened, self-contained record per claim, JSON Lines. Currently empty: no claim ledger exists yet
  • /data/claims/index.json · fingerprints, first issue, grade, and citation list — the join between per-issue ledgers and source records

Indicators are not published, per classification spec §9, and the export does not change that. Every claim record carries text, grade with its meaning in words, source name and type, evidentiary status, every mark, entities, the time block, the assertion license, and a resolvable link back to where it was published — never an indicator list.
